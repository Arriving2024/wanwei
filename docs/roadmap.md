# 路线与验收

更新：2026-10-19。每阶段以可重复证据完成，不用“已打包”代替“可传文件”。当前固定夹具实测结果见[文件实验记录](p0-file-transfer.md)。用户已授权速度优先实验必要时临时断开原 Wi-Fi；结束后核验恢复，详见[新路线](speed-priority-wifi.md)。

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 连接实验室（已有基线） | 原生发现、用户确认、实际端点和有界清理；跨端构建 | 源码可构建，失败不会遗留本次资源。无线结果按设备记录，不能以 CI 代替 |
| 安全互传（0.3.1 源码，逐项实测） | 对端身份确认、TLS 1.3、绑定真实 P2P 地址、固定 1 MiB 合成数据安全保存、取消 | 双向文件哈希一致，拒绝与中断有效；无共同 AP 仍能传输。USB 辅助预授权不代替普通确认流程验收 |
| 保网与自动选路 | 保网优先和速度优先分开；监测双方原 AP，探索跨频段组合及有界回退 | 保网模式覆盖传输前、中、后；速度模式允许临时换网但核验恢复；失败和清理未确认不得自动重试 |
| 性能与体验 | 大文件、进度、剩余时间、断点恢复、可选提速 | 同条件比较吞吐、延迟、温度与能耗，不承诺断开 Wi-Fi 必然更快 |
| Apple 跨端与多链路 | Apple 真机能力/签名/配对；逐对验证跨端；研究多路径 | 单机能力不替代跨端互通。两条路径确实并存并承载数据后再评估聚合 |
| 投屏 | 捕获、编码、同步、拥塞控制与显示 | 单独报告画质、端到端延迟和网络影响；文件无损不意味着画面无损 |

操作目标是“选文件 → 选设备 → 接收方接受”。首次必要的系统授权正常呈现；不要求共同路由器，不把切换对方热点当成保网直连通过。

首版优先可靠的单链路传输。Wi-Fi 7 标识不能证明本次 Direct 支持 MLO；Wi-Fi 6 软件聚合也必须先有两条真实、可同时到达对端的路径。iOS/iPadOS 使用独立系统适配层，不沿用 Android 频段控制假设。
