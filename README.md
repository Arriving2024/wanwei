# 万维计划 · Wanwei

探索 Windows、Android、iOS 与 iPadOS 之间按需建立的 Wi-Fi 直连：无需共同路由器，并尽可能保留双方原 Wi-Fi。

状态复核：2026-10-19；新增[速度优先的独立本地 Wi-Fi 实验](docs/speed-priority-wifi.md)，允许必要时临时换网并核验恢复。

新路线已完成荣耀创建临时网络、Windows 真实接入、双向各 1 MiB 固定文件的 TLS 1.3 认证传输与独立落盘哈希核验，结束后电脑原网络恢复确认。Windows / Android 分别通过 430 / 82 项本地检查。协商为 Wi-Fi 6、收发链路速率均 1201 Mbps；本轮使用 USB 辅助实验授权，普通确认流程、用户文件、吞吐及 MLO 仍待验证，尚未包含在现有下载包中。

**Windows / Android 0.3.1 已通过双向固定数据实测，每个方向各 1 MiB；0.3.2 开发版已通过普通界面的 Windows → Android 1 MiB 收发。** 两轮均使用 TLS 1.3 双向认证和完整公钥指纹绑定，并核验接收端保存及独立磁盘哈希。当前仅收发程序生成的测试数据，尚不支持选择用户文件；0.3.2 反向收发、连续保网、吞吐、投屏及 Apple 跨平台互通仍需验证。

开发中的 Windows / Android **0.3.2** 增加原生直连上的自动接收端口提示和 Android 已建立连接消失的独立清理确认；本地分别通过 315 / 62 项检查；新增的17项检查覆盖独立建组探针策略。2026-10-17 的普通界面实验已验证自动端口交换、首次完整公钥信任、逐次 OFFER 接收和 Windows → Android 落盘；本轮 Windows 本应用原生资源释放与 Android 已建立组清理均已确认。Android → Windows 尚未真正发起发送，连续重连仍待验收。Windows 对既有关联时精确的设备枚举错误增加一次受原时限约束的恢复尝试，真实效果尚待验证。UDP 端口提示不提供身份认证。Apple **0.1.1** 增加系统配对准备入口，不创建数据连接；已通过 Mac 不签名编译，签名与真机仍待验证。0.3.2 尚未发布，上述开发改动尚未包含在 0.3.1 下载包中。

开发源码 `3110743` 的 Windows、Android 和 Apple 不签名编译三个[云端检查任务](https://github.com/Arriving2024/wanwei/actions/runs/39101508456)均已通过；这一结果仅覆盖该提交，不包含后续维护者脚本改动，也不代表反向普通流程或 Apple 真机已通过。

Windows 0.3.2 后续开发包增加“开始 1 MiB 文件互传”入口，同次点击启用文件模式，并在实际开始等待后更新主界面状态；配对提示增加最多3次任务栏闪烁及真实窗口绘制状态记录。解压包315项检查与显示真实窗口的无无线检查通过，包括最小化恢复、默认拒绝、过期点击及取消清理。它们不能证明用户已看到提示，新窗口流程的现场双端验收仍待完成。

2026-10-17 的 0.3.2 实验中，手机原 AP 与 Direct 组均为 5745 MHz，160 个 Wi-Fi 样本包含传输期间的 29 个样本，未观察到原 AP 变化或丢失；采样达到上限，未测试连续互联网。该结果仅支持本轮同信道 5 GHz 并存，不代表双射频或 MLO 聚合。USB 调试线仍连接，仅用于读取报告及保存文件的大小和摘要，未搬运文件内容，物理拔线仍待验收。原始设备报告和个人媒体不在公开仓库中。

同日后续反向实验中，一轮已建立 Direct，但在准备收发操作时耗尽180秒窗口，未启动文件传输；另一轮手机要求断开原 WLAN，持有人拒绝，Windows 报 `0x80004005`，双方均未观察到已建立连接。后一轮没有实际 P2P 频率，不能根据原 AP 的5745 MHz推断组频率或设备只有一个5 GHz接口。两轮 Windows 本应用资源释放及 Android 自有连接清理或取消后无组均已确认，临时防火墙规则已独立核验移除。此前单向1 MiB通过仍有效，但这些后续结果说明保网建连尚不稳定，不能将采样一致称为持续联网。详见[现场结果与下一步探测](docs/p0-file-transfer.md#后续反向实验与保网边界)。

## 使用与构建

下载 [0.3.1 预发布版](https://github.com/Arriving2024/wanwei/releases/tag/p0-0.3.1)，包含 Windows 便携 ZIP、Android Debug APK 和 SHA-256 校验文件。Android 保存兼容修复已在上述设备组合上验证；连续重复投送与普通确认流程仍待验收。没有 Apple 签名安装包。此前的 [0.3.0](https://github.com/Arriving2024/wanwei/releases/tag/p0-0.3.0) 和[连接实验版](https://github.com/Arriving2024/wanwei/releases/tag/lab-2026.10.14)保留为历史版本。

- Windows：便携实验包完整解压后运行 `Wanwei.Windows.exe`；自行构建可运行根目录 `Start-Windows.cmd`。见 [构建说明](docs/building.md) 和 [便携包说明](docs/windows-portable-package.md)。
- Android：使用 Android Studio 或 Gradle wrapper 构建 Debug APK，安装后名为“万维实验室”；[构建说明](docs/building.md) 列出 SDK 与权限要求。
- iPhone / iPad：可在 Windows 编辑源码，在兼容的 Mac + Xcode 上编译、签名和真机调试。开发者模式不能代替 Mac 构建环境，见 [Apple 上机步骤](docs/apple-p0-quickstart.md)。

0.3.1 源码提交 `f37fe88` 的 Windows、Android 与 Apple 未签名编译三个[云端检查任务](https://github.com/Arriving2024/wanwei/actions/runs/38673423408)均已通过。表中的检查计数来自本地验证；自动检查不能替代现场的确认、保存和保网验收。

文件实验需先核对双方完整 64 位 SPKI SHA-256 指纹，监听与发送均绑定实际原生 P2P 地址。0.3.1 的端口及身份通过线下参数交换；0.3.2 在支持的角色下自动交换端口，首次完整公钥仍须核对。调试版的 USB 辅助入口仅限固定数据实验，报告明确区分实验预授权与普通界面接收；10 月 17 日的单向普通流程未启用该预授权。见[实验步骤](docs/p0-file-transfer.md)。

Android Debug APK 已具备安装所需的调试签名；Windows 尚未做可信发布者代码签名。个人设备报告、私钥、受保护身份文件、实验 nonce、手机照片及本机路径资料留在本地，不上传公开仓库。

## 开发方向

保网优先尽可能保留双方现有 Wi-Fi，速度优先允许必要时临时换网并在结束后核验恢复。已连 5 GHz 时可尝试兼容的 2.4 GHz Direct；已连 2.4 GHz 时探索 5 GHz Direct，不硬编码设备必然支持。保网测试遇到断网要求应退出；速度优先的新本地 Wi-Fi 路线尚未接入文件传输，不能宣称 Wi-Fi 7 MLO 已实现。

Android 0.3.2 开发版（build 11）新增“检测 2.4 GHz 独立直连”入口，新增17项策略测试，本地总计62项、编译、Lint和Debug APK v2签名校验通过。2026-10-18 荣耀真机完成一次自主空组检测：实际组为2412 MHz、手机为组主、无客户端；原 Wi-Fi为2437 MHz，17个采样点保持同一 AP、无丢失事件。10秒观察后仅移除本轮自有组，连续缺席回读确认清理，重试未锁定；临时开启的定位已恢复关闭。本轮原 Wi-Fi也是2.4 GHz，尚未验证“原5 GHz＋2.4 GHz直连”、Windows加入、文件收发或持续互联网，不计入文件成功结果。详见[检测结果与边界](docs/p0-file-transfer.md#后续反向实验与保网边界)。Android 的频段参数在创建组与加入组时含义不同，不能强制远端组主换频；Windows 当前采用的公开接口提供组主角色偏好，没有可直接对应的频段参数。

下一步验收 0.3.2 普通流程反向收发、连续重连及清理、负载下保网与物理拔线，再扩展用户文件、自动选路、性能、多链路与投屏。见[路线与验收](docs/roadmap.md)、[P0 协议契约](protocol/README.md)、[开源复用方案](docs/github-reuse-plan.md)。
